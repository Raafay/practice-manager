# Security review (Stage 13)

Done on 14/10/2026, before any real client data. Three separate review passes read the whole codebase. None of them had written the code. Each finding was checked against the code, or shown with a test, before it was fixed. The findings were then fixed most serious first, and each fix has a test. The fourteen checks come from `docs/specs/12-deploy-and-operations.md` section 1.

The short version: there were no critical findings. One high finding (F1) let a person who manages users become owner, and it is fixed. One more (F2) would have become high as soon as the app ran behind a host's proxy; it is fixed too. Everything else was medium or low. All of it is fixed, apart from the items listed under "Not fixed" at the end.

## The fourteen checks

| # | Check | Result |
|---|---|---|
| 1 | Every staff address refuses signed-out and portal users | **Pass, with a new test.** `apps/core/tests/test_url_walk.py` visits every address in the project. It does this as six kinds of user: signed out, portal, staff, manager, owner, and "limited" (staff with no rights). It uses real records from the demo data and checks each answer against a table. A new address with no line in the table fails the test. The Django admin (`/control/`) is checked separately and is for the owner only. **Finding F7:** portal users could open allauth's own pages for passwords and two-factor. Fixed. |
| 2 | Portal and public addresses refuse another client's objects | **Pass, after fixes.** Every portal lookup starts from `for_portal_user`, uses `public_id`, and is checked again on each request. **F6:** a colleague at the same client could see another director's saved draft answers (date of birth, home address). **F16:** a colleague could download another person's sensitive upload, such as a passport, if they knew its address. Both fixed. |
| 3 | Rights are checked; finance figures are absent without the right | **Pass, after fixes.** **F1:** a non-owner with `users.manage` could give themselves the Owner role. **F5:** fees showed to roles without `fees.view` in six places, and practice-wide pipeline totals showed without `finance.owner`. **F11:** connecting Xero checked the wrong right. All fixed. Finance pages, exports and the Overview panel already checked `finance.owner` in the view and the template. |
| 4 | File handling | **Pass, after fixes.** Every upload is checked by extension and size, and PDFs and images by their first bytes. Files are stored under random names in private storage with no public address. Downloads go through permission-checked views, as attachments, with `nosniff`. Views of sensitive files are logged. **F13:** nothing capped the size of a request body before it was read, and files could be cached. Fixed. |
| 5 | Tokens | **Pass.** Action-link and invitation tokens are 32 random bytes. Only a hash is stored, and it is compared in constant time. They expire and can be used once, under a row lock. Portal codes are six digits, hashed with the secret key, and last 10 minutes. Request-link tokens are readable on purpose (CORRECTIONS 20) and compared in constant time. **F12:** the portal code try counter was not atomic. Fixed. |
| 6 | Sign-in | **Pass, after fixes.** django-axes locks an account for 15 minutes after 5 wrong passwords from one address. Two-factor is enforced on every staff page. Sessions end after time limits for both staff and portal users. **F3:** nothing limited guesses at the six-digit two-factor code per person. **F8:** making new recovery codes crashed. **F11:** inviting a user, connecting Xero and downloading import failures did not ask for the password again. All fixed. |
| 7 | CSRF, rich text, no unsafe output | **Pass.** No view switches off CSRF protection. The only exception is the email provider's delivery webhook, which is server to server and checked by a shared secret instead. HTMX sends the token. Every `|safe` was traced either to text cleaned by nh3 or to an escaping builder. nh3 allows only `a[href]` with http, https or mailto. |
| 8 | Queries | **Pass.** There is no raw SQL, `.extra()` or cursor use in the app's own code (`/healthz` runs a fixed `SELECT 1`). Sort keys come from allow-lists. |
| 9 | Headers and cookies | **Pass, with new tests.** `apps/core/tests/test_headers_live.py` sends requests through the app with the production settings switched on. It checks HSTS for a year, the CSP, `Referrer-Policy: same-origin`, `nosniff`, `X-Frame-Options: DENY`, and that cookies are Secure, HttpOnly and SameSite Lax. It also checks that plain HTTP is redirected. `manage.py check_headers https://…` runs the same check against the live site (GO-LIVE). |
| 10 | Secrets; encrypted fields | **Pass.** Git history (79 commits) holds no keys, tokens, `.env` files or real addresses. The demo password and the development code `000000` cannot work in production, because `prod.py` refuses to start. National Insurance numbers, UTRs, Companies House codes, HMRC codes, Xero tokens, import files and portal secret answers all use the encrypted field. They are shown masked, and every reveal is logged. **F15:** a reveal could be filed on an unrelated client's timeline. Fixed. |
| 11 | Rate limits | **Pass, after fixes.** Sign-in, portal codes (asking and checking), request links and action links are all limited. **F2:** every limit, the lockout and the audit log used the address of the host's proxy, not the visitor's, so one person could lock out everyone. Fixed: the visitor's address now comes from the trusted proxy header. |
| 12 | Dependencies | **Pass.** `pip-audit` 2.10.1 against `uv.lock`, both production and development packages: "No known vulnerabilities found" (14/10/2026). Repeat monthly (RUNBOOK). |
| 13 | Logs and error pages | **Pass, after fixes.** **F4:** tokens in addresses could reach the logs through Django's CSRF warnings and server-error lines. Fixed: every log line now goes through a filter that takes tokens out. Error pages are generic. Optional Sentry reports are scrubbed of request data, cookies, headers, users, local variables and error text. |
| 14 | CSV exports and formulas | **Pass.** Every CSV goes through `safe_cell`. Exports need `data.export` and the password again, and they are logged. **F14:** the import screens showed tax references from columns that had not been matched to a field. Fixed. |

| # | Severity | Finding | Fix | Test |

## Not fixed, and why

The owner should read and accept these. The go-live checklist asks for the first one in writing.

- **Uploaded files are not virus scanned.** This was planned (spec 01 section 7). Files are only ever downloaded as attachments or previewed as PDF or image, never run.
- **Rate-limit counters are not fully atomic.** They use the database cache's increment, which reads and then writes. When requests arrive at exactly the same moment, a limit can undercount by a few. The account lockout (django-axes) and portal code tries use the database directly and are exact.
- **Portal sign-in timing.** When an email belongs to a portal user, the code email is sent during the request, so that answer takes slightly longer. The page wording is the same either way. A later change could send the code from the job queue.
- **PDF previews are not sandboxed.** A CSP `sandbox` header stops Chrome's PDF viewer from working. Previews are limited to PDF, PNG, JPEG and WebP. Each is checked by its first bytes and served with `nosniff`.
- **HEIC uploads are checked only for the `ftyp` marker.** HEIC files are never previewed, only downloaded.
- **PDF copies of proposals and engagement letters** in a client's Documents tab show fees to anyone who may open documents. This matters only if the owner takes `fees.view` away from a role. By default every role has it.
- **Activity log lines are never edited.** After a person is removed for good, older lines that name them (for example "Sam Sample was linked to …") stay as the audit trail. The removal itself is logged without the name.
- **The host's own request log** records full addresses, which can include action-link tokens. Gunicorn's access log is off. Keep the host's log retention short (DEPLOY.md).
- **Amazon SES delivery reports.** Anymail does not check Amazon's SNS message signature. The webhook is protected by a long shared secret over HTTPS instead, the same as for Postmark and Brevo.
- **HSTS preload is off on purpose.** Joining the preload list is hard to undo while the domain may still change.
- **Inline styles are allowed** by the CSP (CORRECTIONS 25). Scripts stay strict.
